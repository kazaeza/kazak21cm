# FigCraft через сервер

Файл живёт у человека в приложении FigCraft. Человек делится им через сервер, агент заходит в тот
же файл из `figcraft-cli mcp`. Правки идут через сервер в обе стороны: агент меняет макет, а
человек видит это у себя сразу. Пересылать сам файл не нужно.

```
FigCraft у человека ──(Share ▸ Online)──► сервер ◄──(collab.join)── figcraft-cli mcp у агента
```

Команды макета (слои, свойства, экспорт) описаны в скилле `figcraft`
(`.claude/skills/figcraft/references/commands.md` и `node-properties.md`). Этот скилл про
подключение, синхронизацию, сервер и сами файлы.

| Справочник | Что там |
|---|---|
| `references/own-server.md` | Свой `figcraft-server`: установка, TLS, хранение на диске, срок жизни файлов, команды админа, что происходит при публикации |
| `references/big-files.md` | Ресурсы облачной сессии, каналы переноса файла (что проверено, что нет), порядок для больших файлов, прямая работа без сервера |
| `references/file-format.md` | Устройство `.figcraft` (zip, `document.json`, `images/<sha256>`, иногда `versions/`), команды `info`/`render`/`export`/`convert`/`run`, картинки, скорость, эмодзи |
| `references/web-build.md` | Веб-версия в headless Chromium: запуск, управление по координатам, эмодзи, сохранение и экспорт загрузкой |
| `NOTES.md` | Что и на какой версии проверено |

## Что выбрать

| Ситуация | Что делать |
|---|---|
| Человек дал код или ссылку | Раздел **A. Зайти в файл** |
| Человек хочет, чтобы агент поработал с файлом у него на ПК | Попросить в приложении **Share ▸ Online ▸ Start sharing** и прислать **код для правки** (для просмотра хватит кода просмотра). Дальше раздел A |
| Нужно выложить файл и дать людям ссылку | Раздел **B**, только по прямой просьбе |
| Файл больше 8 МиБ | Свой сервер: `references/own-server.md` |
| Файл больше примерно 700 МиБ (например, 1 ГБ) | Сначала ужать: раздел **Размер файла**, затем свой сервер. Без сервера: `references/big-files.md` |

| | Публичный `wss://collab.craftapps.dev/` | Свой `figcraft-server` |
|---|---|---|
| Размер файла | **8 МиБ** (`collab.serverInfo` от 2026-11-19). Перед публикацией проверь `maxFileMb` | До ~1 ГБ на сервере (`max_file_mb = 1023`), но см. **Размер файла** |
| Хранение | Удаляется через 30 дней без открытий | Пока не удалят |
| Доступ | Код или ссылка и есть доступ, аккаунтов нет | То же, плюс ключ сервера для публикации |
| Шифрование | Только в пути (TLS). На сервере файл лежит открыто | На вашей машине |

На публичный сервер нельзя класть конфиденциальное: его операторы технически могут прочитать файл.

## Подготовка

1. **figcraft-cli.** Если есть инструменты `mcp__figcraft__*` (локальная сессия с подключённым
   MCP), работай ими: команды те же, помощник не нужен. Иначе скачай CLI:
   ```bash
   WORK=<папка для временных файлов, например scratchpad сессии>
   FIGCRAFT_CLI=$(bash ${CLAUDE_SKILL_DIR}/scripts/get_figcraft.sh "$WORK/figcraft" \
     | sed -n 's/^figcraft_cli=//p')
   ```
   Скрипт берёт Linux x86_64 из официального релиза, сверяет SHA-256 и ничего не запускает. В auto
   mode классификатор пропускает запуск скачанного бинарника только после явного согласия человека.
   Если запуск запрещён, спроси человека и не обходи запрет.
2. **TLS в облачной сессии.** Прокси облака перешифровывает TLS, даже у прямых соединений, а
   figcraft-cli доверяет только встроенному списку Mozilla и файлу из `FIGCRAFT_CA_FILE`. Поэтому
   задай `FIGCRAFT_CA_FILE=/root/.ccr/ca-bundle.crt`: FigCraft берёт все сертификаты из
   PEM-файла. Без этой переменной вход падает с «isn't signed by an authority this app trusts».
   На собственном ПК переменная не нужна.
3. **Сеть.** `curl -sS https://<хост>/healthz` должен ответить `ok`. Если прокси отвечает 403,
   хост не разрешён в окружении: скажи об этом и предложи добавить хост (точное имя, без масок).
4. **Без `--automation-read-root/--automation-write-root`.** С ними сессия не достучится ни до
   одного сервера.

## A. Зайти в файл и поработать

`scripts/figcraft_live.py` запускает `figcraft-cli mcp`, выполняет шаги по порядку и печатает по
JSON-строке на шаг. На первой ошибке помощник останавливается и выходит с кодом 1. Живая сессия
существует, пока работает процесс, поэтому вход, правки, синхронизация и сохранение копии должны
быть в одном файле шагов.

Шаги бывают такие:
- `{"join": "<код или ссылка>", "timeout": 180}` — войти и дождаться статуса `live`;
- `{"command": "<команда>", "params": {…}}` — любая команда FigCraft (`run_command`);
- `{"tool": "<инструмент>", "args": {…}}` — любой MCP-инструмент: `inspect_document`,
  `get_node`, `screenshot`, `export`, `save_file`;
- `{"wait_live": N}` — после `collab.publish` или `collab.share` ждать до N секунд, пока файл не
  загрузится;
- `{"sync": N}` — N секунд опрашивать `collab.peers`, чтобы правки ушли, а чужие пришли;
- `{"leave": true}` — выйти из сессии.

Сначала осмотрись:

```json
[
  {"join": "K7M-2QX-9TD"},
  {"tool": "inspect_document", "args": {"depth": 2, "outline": true}},
  {"tool": "screenshot", "args": {"maxSize": 1200}}
]
```

```bash
FIGCRAFT_CA_FILE=/root/.ccr/ca-bundle.crt python3 ${CLAUDE_SKILL_DIR}/scripts/figcraft_live.py \
  --cli "$FIGCRAFT_CLI" --out-dir "$WORK/shots" "$WORK/look.json"
```

Потом внеси правки отдельным запуском:

```json
[
  {"join": "K7M-2QX-9TD"},
  {"command": "edit.findReplace", "params": {"find": "Капучино 250", "replace": "Капучино 270"}},
  {"sync": 5},
  {"tool": "screenshot", "args": {"ids": [2], "maxSize": 1200}},
  {"tool": "save_file", "args": {"path": "/abs/work/menu-copy.figcraft"}},
  {"leave": true}
]
```

Правила:
- **Id слоёв.** После входа активный документ — файл с сервера, и у него свои id. Узнавай их через
  `inspect_document` или `get_node` в том же запуске, не угадывай.
- **Синхронизация.** Правки уходят на сервер при следующих вызовах, поэтому после правок всегда
  ставь `{"sync": 3–5}`, а для крупных пакетов дольше. Без этого шага выход может оборвать
  неотправленное.
- **Только просмотр.** `access: "view"` или `readOnly: true` означают ссылку для просмотра: правки
  отклоняются с «View only: …». Нужен код для правки.
- **Код со своего сервера.** Код ищется на сервере из настроек, по умолчанию на публичном. Для
  своего сервера сначала выполни
  `{"command": "pref.publishServer", "params": {"url": "wss://host/"}}` или возьми ссылку: в ней
  уже есть адрес.
- **Совместная правка.** В одном текстовом слое побеждает тот, кто закончил последним. Перед
  правкой проверь `{"command": "collab.peers"}` → `peers[].editing` и не трогай слой, где печатает
  человек. Показать, где работаешь: `collab.cursor {x, y}` и `collab.cursorChat {text}`.
- **Большой файл.** При входе приходит весь файл целиком: ставь `"timeout": 900` у `join` и
  смотри раздел **Размер файла**.
- **Имена слоёв.** `edit.findReplace` меняет текст, но не имя слоя. Слой, названный по своему
  тексту, сохранит старое имя. Переименование: `set_properties {ids, props: {name}}`.

Забрать файл с сервера себе (HTTP-скачивания у сервера нет, только так):

```json
[{"join": "<ссылка>", "timeout": 900},
 {"tool": "save_file", "args": {"path": "/abs/work/menu.figcraft"}, "timeout": 900},
 {"leave": true}]
```

Почему не получается войти (`join failed: …`):

| Причина | Что делать |
|---|---|
| No session with that code | Код неверный или с другого сервера (см. `pref.publishServer`) |
| That code has expired or its sharing was stopped | Попросить новый код |
| Couldn't reach the server (…) | Сеть или хост: `/healthz`, разрешения окружения |
| Ошибка сертификата | `FIGCRAFT_CA_FILE` (подготовка, пункт 2) |
| Too many wrong codes… | Подождать 15 минут. Коды не перебирать |
| Revoked link / full session | Попросить новую ссылку |

## B. Выложить файл и дать ссылку (только по просьбе)

Публикация отправляет файл на сервер, который держат другие люди. Делай её только по прямой
просьбе и заранее скажи, куда уйдёт файл.

```json
[
  {"command": "collab.serverInfo", "params": {"server": "wss://collab.craftapps.dev/"}},
  {"tool": "open_file", "args": {"path": "/abs/work/menu.figcraft"}},
  {"command": "collab.share", "params": {}},
  {"wait_live": 600},
  {"sync": 3}
]
```

`wait_live` дожидается конца загрузки и возвращает `code`, `share` и `published`. Файл остаётся на
сервере и после выхода помощника.

- Сначала проверь `serverInfo`: если файл больше `maxFileMb`, публикация будет отклонена.
- Используй `collab.share {}` для публичного сервера: получишь код. Для своего сервера с ключом
  нужен `collab.publish {server: "wss://host/?key=…"}`: получишь ссылки.
- Запусти с `--show-secrets`, чтобы увидеть `code` и `share` (или `published.edit` и `.view`), и
  передай их человеку.
- `published.owner` (owner token) показывается один раз, а headless-сессия забывает его на выходе.
  Отдай токен человеку на хранение. Без токена файл на публичном сервере не удалить, он сам
  исчезнет через 30 дней. Удаление:
  `collab.manageFile {file, action: "remove", server, owner}`.

## Размер файла

Картинки идут через сервер внутри документа в base64. Поэтому снимок на сервере примерно в 1,33
раза больше `.figcraft`, если файл в основном из картинок. Замеры на FigCraft 0.18.1:

| `.figcraft` | Снимок на сервере | Что вышло |
|---|---|---|
| 219 МиБ | 306 МБ | Публикация 16 с, вход 13 с, клиенту ~1 ГБ памяти |
| 705 МиБ | 985 МБ | Публикация 47 с, вход 32 с, клиенту 3,3–4,8 ГБ, серверу 4,5 ГБ |
| 961 МиБ | 1,34 ГБ | Не работает: сервер с `max_file_mb = 1023` отказывает («takes at most 1101 MiB»), а с большим лимитом клиент не входит («too large to join here (up to 1024 MB)») |

Это время на одной машине. По интернету добавь передачу снимка в обе стороны. Файл крупнее
примерно 700 МиБ ужми перед публикацией:

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/shrink_figcraft.py --cli "$FIGCRAFT_CLI" \
  big.figcraft small.figcraft --max-side 2048 --quality 85 --work "$WORK/shrink"
```

Что делает скрипт:
- Уменьшает каждую картинку до `--max-side`: в JPEG, а с настоящей прозрачностью в PNG.
- Подменяет картинки командой `image.replace`. FigCraft оставляет старые картинки в файле, поэтому
  скрипт потом выкидывает из архива то, на что ничего не ссылается.

Как проверено:
- Шумовые RGBA-картинки ужались с 961 до 219 МиБ.
- Фотоподобные — со 187 до 1,6 МиБ, раскладка и прозрачность не пострадали.

Перед ужатием спроси, для чего макет:
- для экрана хватит 2048;
- для печати A4 с 300 dpi нужно около 3600.

Исходник не трогай. Результат открой (`figcraft-cli info`, `render`) и покажи человеку.

## Безопасность

- **Секреты.** Коды, ссылки, owner token и ключ сервера работают как пароли. Не коммить их, не пиши
  в README, логи и публичные места.
- **Маскировка.** Помощник по умолчанию скрывает секреты в выводе (`***`). `--show-secrets` нужен
  только в момент, когда ссылку надо отдать человеку.
- **Права.** Код для просмотра, если править не нужно. Правь только то, о чём просили: человек
  видит каждое изменение у себя сразу.

## Проверка

- Шаг `join` вернул `status: "live"`, `access: "edit"` и `readOnly: false`.
- После правок `sync` прошёл без ошибок, а повторный запуск с `join` и `get_node` показывает новые
  значения: это уже с сервера, а не из локальной копии. Ещё лучше, если человек подтвердил у себя.
- Посмотри картинку из `screenshot`, прежде чем говорить, что готово.

## Если figcraft-cli нельзя запустить

Веб-сборка FigCraft тоже заходит в файлы на сервере (File ▸ Join live session…), но управляется
только мышью по canvas, поэтому это медленно и хрупко. Используй её только как запасной путь и
скажи об этом человеку. Как поднять её в headless Chromium, включить цветные эмодзи и забрать
файл, описано в `references/web-build.md`.
