# Сборщики

Всё, что про ВК и Telegram в этом файле, написано без доступа к реальным страницам. Помеченное словом «проверить» это гипотеза.

## 1. ВК: пилот

Цель: выяснить, что именно отдаёт ВК странице чата, и выгрузить историю беседы за последние 30 дней.

### Окружение

- Python 3.11+, `pip install playwright`.
- Запускать установленный Chrome: `launch_persistent_context(user_data_dir=..., channel="chrome", headless=False)`. Если Chrome нет, `playwright install chromium`.
- Профиль браузера: `tasker/.browser-profile/` (в `.gitignore`). Отдельный профиль, не профиль повседневного Chrome пользователя.
- Данные пилота: `tasker/data/probe/` и `tasker/data/vk_history.jsonl` (в `.gitignore`).
- Если доступны расширение Claude in Chrome или встроенный браузер приложения, ими можно разведать страницу. Выгрузку делаем скриптом на Playwright, чтобы она повторялась без ассистента.

### Шаги

1. Открыть окно браузера с профилем, перейти на `https://vk.com`. **Пользователь входит сам** (логин, пароль, код). Скрипт ждёт подтверждения в терминале.
2. Пользователь вручную открывает нужную беседу. Скрипт записывает URL и определяет идентификатор беседы. Адрес не угадываем: форматы адресов нового и старого мессенджера ВК отличаются (проверить).
3. Включить запись ответов сервера: `page.on("response", ...)` для доменов `vk.com`, `api.vk.com` и родственных. Для каждого ответа сохранять: URL, метод, тело запроса, статус, content-type, тело ответа как текст.
4. Медленно прокрутить историю вверх 3-5 раз, не чаще одной подгрузки в 2-3 секунды. Убедиться, что подгрузка старых сообщений тоже видна в сетевых ответах.
5. Разобрать записанное и ответить на вопросы:
   - Есть ли в ответах номер сообщения, автор, время, текст, `reply`/`forwarded`/`attachments`, признак правки и удаления?
   - В каком формате ответ (чистый JSON, JSON внутри обёртки, HTML-фрагмент)?
   - Как запросить сообщения «новее номера N» и «старше номера N»?
   - Есть ли расшифровка голосовых?
6. Если данных в сетевых ответах достаточно: читаем их. Если нет: запасной вариант, разметка страницы (DOM). Атрибуты вроде `data-msgid` это гипотезы, проверить на живой странице.
7. Записать выводы в `docs/vk-probe-findings.md` **без текстов переписки**.

### Запуск скрипта пилота

Скрипт `collector/vk_probe.py` делает шаги 1-4 (вход делает пользователь, запись ответов включается только после его Enter, прокрутка медленная, на капче скрипт останавливается). Проверен на локальной заглушке, на живом ВК не запускался: формат ответов ВК и место прокрутки истории нужно проверить.

```bash
cd tasker
python -m venv .venv
.venv/Scripts/pip install -r collector/requirements.txt   # Linux/macOS: .venv/bin/pip
.venv/Scripts/python collector/vk_probe.py                # Linux/macOS: .venv/bin/python
```

Разбор записанного (шаг 5) и `docs/vk-probe-findings.md` делает ассистент в локальной сессии.

Записи пилота содержат не только целевую беседу, но и список диалогов с превью других личных переписок. Файлы `data/probe/` не коммитим и никуда не отправляем. Выгрузку истории делаем только по одной беседе.

### Выгрузка истории

- Период по умолчанию 30 дней (уточнить у пользователя).
- Прокрутка вверх до нужной даты, пауза 2-3 секунды между подгрузками, остановка при капче или ошибке.
- Результат в формате архива (`ARCHITECTURE.md`, раздел 3), по строке на сообщение: `data/vk_history.jsonl`.
- Проверка: количество сообщений по дням, отсутствие дублей и дыр в нумерации, порядок, реплаи ссылаются на существующие сообщения, правки и удалённые видны. Показать пользователю несколько мест из чата и сверить с экраном.

### Чего не делаем

- Не пишем в поле сообщения, не отправляем, не ставим реакции.
- Не решаем капчу, не обходим подтверждения. Останавливаемся и говорим пользователю.
- Не получаем токены «как у официальных приложений ВК». Официальный API с пользовательским токеном рассматриваем, только если пользователь сам выдаст токен нормальным способом. Я не уверен, что токен с доступом к личным сообщениям сейчас можно получить (проверить, но на это не рассчитывать).
- Не маскируемся под другое устройство и не подменяем окружение браузера.

### Пометка «прочитано»

Открытие беседы помечает сообщения прочитанными в аккаунте пользователя. Он с этим согласен. Для клиента это значит, что его сообщения видны как прочитанные, хотя ответа может не быть. Если для пилота важно, можно зафиксировать, что именно видит другая сторона.

## 2. ВК: боевой сборщик (после пилота)

- Постоянный профиль, запуск без окна. Расписание: пн-пт 9:00-19:00, раз в 3 минуты.
- Каждый проход: новые сообщения по курсору, плюс перечитывание последних 50 для правок и удалений.
- Сообщения шлёт на сервер по HTTPS с токеном. Сам модель не вызывает.
- Ошибки и слёт сессии: уведомление в Telegram пользователю, статус «данные устарели с…» в таскере.
- Живёт на компьютере пользователя, пока сессия стабильна. Компьютер должен быть включён и не засыпать в рабочие часы.

## 3. Telegram: бот

Всё ниже проверить на реальных чатах.

- Токен бота создаёт пользователь через BotFather. Токен храним в `.env`.
- По умолчанию бот в группе видит только команды и ответы на свои сообщения. Режим приватности выключается в BotFather (`/setprivacy` → Disable). После этого бота нужно удалить из чатов и добавить заново.
- Бот видит: новые сообщения, правки, реплаи, пересылки, вложения, голосовые, темы в чатах с форумным режимом (`message_thread_id`). Реакции только если бот админ и в `allowed_updates` есть `message_reaction`.
- Бот не видит: сообщения до своего добавления и удаления сообщений.
- Сообщения для бота Telegram хранит около суток. Если бот простоял дольше, пропущенное не вернуть. Поэтому бот работает на сервере 24/7.
- Начальный режим: long polling (проще). Webhook можно позже.
- В чатах появится участник-бот, который сохраняет переписку. Команду нужно предупредить.
- История: экспорт чата в Telegram Desktop (JSON за нужный период). Конвертер в формат архива.
- Голосовые: аудио в Gemini или расшифровка на стороне Telegram, если доступна.
- Тот же бот шлёт уведомления пользователю в личку.
