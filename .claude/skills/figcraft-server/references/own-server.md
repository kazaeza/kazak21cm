# Свой figcraft-server (для больших файлов)

Публичный сервер принимает только небольшие файлы (у открытого сервера по умолчанию до 16 МиБ). Для
файла около 1 ГБ нужен свой `figcraft-server` с поднятым `max_file_mb`. Полная документация лежит в
архиве сервера: `server.md`, раздел «Deploy on a Linux server».

## Где запускать

- **На машине, доступной из интернета** (VPS, сервер в офисе с белым адресом и доменом), если
  в файл будет заходить облачная сессия: ей нужен публичный адрес `wss://…`.
- **Домашний ПК без проброса порта** подходит только для работы в той же сети.
- **Сам сервер** работает без графики, только на родных платформах, веб-сборки у него нет.

## Шаги

1. Скачай сервер:
   `bash get_figcraft.sh /opt/figcraft --server` (печатает `figcraft_server=…`).
2. Напиши `/etc/figcraft-server/server.toml`:
   ```toml
   listen = "127.0.0.1:47900"
   data = "/var/lib/figcraft-server"
   public_url = "wss://figcraft.example.com/"
   trusted_proxy = "127.0.0.1"
   max_file_mb = 1023   # больше не имеет смысла: клиент не входит в файл со снимком > 1024 МБ
   ```
   Снимок примерно в 1,33 раза больше `.figcraft`, если файл в основном из картинок. На таком
   сервере живьём работают файлы примерно до 700 МиБ, крупнее надо ужать (`SKILL.md`, «Размер
   файла»).
   Не включай `open_publish` для такого сервера: публиковать сможет только тот, у кого ключ.
3. Проверь настройки: `figcraft-server --config /etc/figcraft-server/server.toml check`.
4. Запусти как службу: `figcraft-server.service` из архива (пользователь `figcraft`,
   `ExecStart=/usr/local/bin/figcraft-server --config /etc/figcraft-server/server.toml`).
5. Настрой TLS через Caddy (`Caddyfile` из архива): блок с вашим доменом и
   `reverse_proxy 127.0.0.1:47900`. Caddy сам получит сертификат и пропустит WebSocket.
6. Получи адрес для публикации: `figcraft-server --config /etc/figcraft-server/server.toml key`
   печатает `…/?key=<ключ>`. Ключ работает как пароль администратора.
7. Проверь доступность: `curl https://figcraft.example.com/healthz` должен ответить `ok`.

## Как сервер хранит файлы

- **Каталог данных** (`--data`):
  - `server.key` — ключ сервера, открытым текстом;
  - `files/<id>/meta.json` — имя и даты;
  - `links.json` — ссылки, только хеши токенов;
  - `snapshot.bin` — снимок на последнее сжатие;
  - `log.bin` — журнал изменений после снимка.

  Один каталог — один сервер: второй процесс на нём не запустится (`LOCK`).
- **Как растёт.** Снимок примерно в 1,33 раза больше `.figcraft`, если файл в основном из картинок
  (они идут в base64). Журнал сжимается в новый снимок после 1000 записей или 16 МиБ, когда все
  вышли, и при остановке.
- **Срок жизни.** Файл остаётся на сервере, когда все вышли. Опубликованный **с ключом** живёт, пока
  его не удалят. Опубликованный **без ключа** (открытый сервер, `collab.share`) удаляется через
  `idle_days` (30) без открытий. Удалить его может владелец по owner token или админ.
- **Как забрать файл.** HTTP-скачивания у сервера нет: на порту только WebSocket и `/healthz`.
  Получить `.figcraft` можно только клиентом FigCraft — войти и сохранить:
  `[{"join": "<ссылка>"}, {"tool": "save_file", "args": {"path": "/abs/x.figcraft"}}, {"leave": true}]`
  (проверено).
- **Остановка.** `SIGTERM` или `SIGINT` (Ctrl+C): сервер сохраняет и сжимает открытые файлы и
  выходит с кодом 0 (проверено). По документации клиенты потом переподключаются сами, а
  подтверждённое не теряется даже при жёстком убийстве: журнал пишется на диск до ответа клиенту.
- **Резервные копии.** Копируй каталог при остановленном сервере. `figcraft-backup.timer` из архива
  делает это каждую ночь и хранит 7 архивов. В копиях лежит ключ сервера, береги их так же.
- **Владелец.** Owner token хранится в настройках приложения на компьютере, где файл
  опубликовали (`state.json`), и показывается один раз. Headless `figcraft-cli mcp` забывает его
  на выходе. Файл, опубликованный с ключом, принадлежит админу сервера, токена у него нет.

## Команды админа (`--config` или `--data`)

| Команда | Что делает |
|---|---|
| `figcraft-server key` | Адрес для публикации с ключом. Работает и при запущенном сервере (проверено) |
| `figcraft-server check` | Проверка `server.toml` (проверено). Предупреждает про `max_file_mb > 1023` |
| `figcraft-server files [--sort size\|age\|idle]` | Список файлов: размер, люди, простой, срок |
| `figcraft-server files remove ID` | Удалить файл навсегда |
| `figcraft-server links list/create/revoke …` | Ссылки файла. Новая показывается один раз, потерянную не восстановить |
| `figcraft-server block-ip IP`, `reports` | Блокировки и жалобы |

В логе сервера видна каждая публикация: `event=published file=<id> bytes=<размер снимка>`. По `bytes`
удобно сверять реальный размер снимка с лимитом.

## Публикация: что происходит (проверено)

1. `collab.publish {server: "ws(s)://host/?key=…", name}` сразу отвечает `connecting`. Документ
   только для чтения, пока идёт загрузка.
2. `wait_live` дожидается `live`. В `published` будут `edit` и `view` (ссылки с токенами), `file`
   (id) и `server`. Для открытого сервера ещё `owner` и `expires`.
3. Если снимок не влез, сервер отвечает «message too large: this server takes at most N MiB at
   once». Если влез, но больше 1024 МБ, клиент отвечает «This file is too large to join here (up to
   1024 MB)».
4. `collab.share` на сервере с ключом тоже даёт короткий код. Чтобы войти по коду, у входящего в
   настройках должен быть этот сервер (`pref.publishServer`). Иначе код уходит на публичный сервер
   и не находится.

## Как человек выкладывает файл

В приложении: **File ▸ Publish to server…**, там адрес с ключом и имя файла. Затем в **Share**
скопировать ссылку для правки и передать агенту. Можно и с кодом: в Preferences указать свой сервер
(`wss://figcraft.example.com/`) и нажать **Share ▸ Online ▸ Start sharing**.

## Ресурсы (замеры на 0.18.1)

| `.figcraft` | Пик памяти сервера | Снимок на диске |
|---|---|---|
| 219 МиБ | 1,5 ГБ | 306 МБ |
| 705 МиБ | 4,5 ГБ | 985 МБ |

- **Память.** Служба из архива ограничена 60–75 % памяти машины. Под файл около 700 МиБ бери
  машину на 8 ГБ, под файл до 300 МиБ хватит 4 ГБ.
- **Диск.** Должен оставаться свободный 1 ГиБ плюс место на два самых больших файла, иначе сервер
  перестаёт принимать изменения. Ночные копии (`figcraft-backup.timer`) занимают ещё столько же.
- **Вход.** Каждый вход передаёт весь снимок: закладывай сеть с обеих сторон.

## Облачная сессия и свой сервер

- Если прокси облака отвечает 403 на ваш домен, хост нужно разрешить в окружении: точное имя,
  без масок.
- Если сертификат выдан Let's Encrypt, хватит `FIGCRAFT_CA_FILE=/root/.ccr/ca-bundle.crt`, как
  для публичного сервера.
