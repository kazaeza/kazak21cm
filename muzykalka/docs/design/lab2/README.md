# Лаборатория 2: шар с нуля (O-38) и звук с нуля (O-39)

Стенд: https://claude.ai/artifact/X5C5TNV41edUXAKJPpgB5D. Здесь его исходники и эталоны. В приложении ничего из
этого нет: сначала пользователь выбирает на стенде, потом пишется бриф и код.

| файл | что это |
|---|---|
| `orbs.js` | три тела шара на WebGL 2: `ink` (жидкость), `thread` (нить), `sand` (песок) |
| `frames.js` | раскадровка тела без телефона: `node frames.js ink out.png 7` (7 — ступень в полутонах) |
| `synth.js` | эталон звука: три инструмента (дрон + нота), стерео, зал, хорус, PADsynth; и «как в 0.0.59» для сравнения |
| `analyze.js`, `analysis.txt` | измерения эталона: уровень, пик, центроид и его ход, ширина стерео, шов петли, высота, атака, хвост |
| `page.template.html`, `build.py` | страница стенда и её сборка в один файл (`out/`) |

```bash
cd docs/design/lab2
node analyze.js > analysis.txt   # таблица звука
node frames.js sand out.png 4    # раскадровка (Playwright с Chromium; чернила на программном рендере ~1,5 мин)
python3 build.py                 # out/muzykalka-lab2.html
```

## Шар: одно правило и три вещества

Отзывы на 0.0.53 и 0.0.59: «рябь просто сверху эффектом», «ни зерно, ни рипплы не нравятся». Правило для всех трёх
прототипов: **шар сделан из одного вещества, а щипок и ответ — силы, приложенные к нему.** Отдельного слоя
«эффект» нет, поэтому наклеить его нечем.

| | что это | щипок вопроса | ответ (ступень p:q) | перенос на Android |
|---|---|---|---|---|
| Чернила | двумерная жидкость (Навье — Стокс, 192², краска 512²) в стеклянном шаре | радиальный толчок из точки и облачко светлой краски | шар очищается и окрашивается в цвет ступени; p струй из середины, прямых у простых отношений и закрученных у резких | нужен GLES 3 (`TextureView`, FBO «пинг-понг»): AGSL не хранит состояние между кадрами. Новый путь рисования → ADR. Зависимостей нет |
| Нить | одна замкнутая струна, 3200 точек, след как на экране осциллографа | две волны бегут по струне, высокие гармоники гаснут первыми (как у струн Тира) | кольцо разматывается в обмотку по сфере: `z = s·cos(q·u)`, долгота `p·u`; резкие ступени ползут | `Canvas` + `Path` или AGSL; дёшево |
| Песок | 30 000 крупинок на круглой пластине, фигуры Хладни `J_p(k·r)·cos(p·θ)`, `k` — q-й нуль функции Бесселя | песок подбрасывает, он снова ложится в линии | крупинки перетекают в фигуру: p диаметров и q колец | `Canvas.drawPoints`; счёт на Kotlin (30 000 × несколько синусов на кадр) |

Правило ADR-015 не затронуто: щипок вопроса высоты не показывает ни в одном из трёх.

Что у ассистентов (по открытым воссозданиям, официальных описаний нет): Siri до iOS 18 — складывающиеся цветные
пятна, раздуваемые громкостью; iOS 18 — свечение по краю; Google — точки и полосы громкости, в Material 3
Expressive — морфинг простых форм; ChatGPT / ElevenLabs — шум в круге на шейдере; сфера из ~3000 точек по спирали
Фибоначчи. Общее: картинку ведёт звук, свет складывается, движение пружинит.

## Звук: почему дёшево и что вместо

В 0.0.59 выход **моно** (`CHANNEL_OUT_MONO`), дрон — одна неподвижная волновая таблица из двух осцилляторов, сухой;
у ноты комната 0,55 с на уровне 0,16. Корреляция каналов 1,00, центроид дрона стоит на месте.

Новое (все три — дрон и нота как один инструмент в одном зале):

| | дрон | нота | зал |
|---|---|---|---|
| Танпура | 4 струны по кругу (1,35 с на щипок); пила → ФНЧ (тело) + полосовой фильтр, съезжающий с 20-й гармоники к 4-й (дживари) | бамбуковая флейта: подъезд −30 центов, дыхание, вибрато только у долгой ноты | 2,6 с |
| Аналог | 7 пил на ноту (±11 центов, разведены по стерео) → ФНЧ 4-го порядка, медленно дышит → хорус | две пилы ±5 центов (слева и справа) + синус → ФНЧ с огибающей | 3,2 с |
| Стекло | PADsynth: каждый обертон — узкая полоса шума; таблица читается в двух местах (лево/право) | FM-колокольчик на атаке + синус, который держит высоту + выдох хора | 4,5 с |

Зал — 8 линий задержки с матрицей Хаусхолдера, 4 диффузора на входе, две линии «дышат» длиной. Петли дронов на
стенде точные по построению (каждая частота и каждый LFO укладываются в петлю целое число раз) — это нужно только
странице; в приложении дрон считается в реальном времени.

Что это значит для приложения (в бриф, когда пользователь выберет): стерео-выход (`CHANNEL_OUT_STEREO`,
`render` в два канала) — затрагивает `audio` и `core:dsp`; зал работает всегда, пока звучит дрон; таблицы PADsynth
считаются не в звуковом потоке (смена тональности); «квинта в танпуре» меняет состав дрона — это решение
пользователя, а не звукорежиссёра.

**Никто в сессии этого не слышал.** Числа в `analysis.txt` говорят, что высота верна, петли без шва, стерео широкое
и спектр движется; красиво ли это — решает только пользователь на стенде.
