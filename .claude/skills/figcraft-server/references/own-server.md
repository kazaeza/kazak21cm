# Свой figcraft-server (для больших файлов)

Публичный сервер принимает только небольшие файлы (у открытого сервера по умолчанию до 16 МиБ). Для
файла около 1 ГБ нужен свой `figcraft-server` с поднятым `max_file_mb`. Полная документация лежит в
архиве сервера: `server.md`, раздел «Deploy on a Linux server».

## Где запускать

- **На машине, доступной из интернета** (VPS, сервер в офисе с белым адресом и доменом), если
  в файл будет заходить облачная сессия: ей нужен публичный адрес `wss://…`.
- **Домашний ПК без проброса порта** подходит только для работы в той же сети.
- **Сам сервер** работает без графики, только на родных платформах, веб-сборки у него нет.

## Шаги

1. Скачай сервер:
   `bash get_figcraft.sh /opt/figcraft --server` (печатает `figcraft_server=…`).
2. Напиши `/etc/figcraft-server/server.toml`:
   ```toml
   listen = "127.0.0.1:47900"
   data = "/var/lib/figcraft-server"
   public_url = "wss://figcraft.example.com/"
   trusted_proxy = "127.0.0.1"
   max_file_mb = 1023   # больше не имеет смысла: клиент не входит в файл со снимком > 1024 МБ
   ```
   Снимок примерно в 1,33 раза больше `.figcraft`, если файл в основном из картинок. На таком
   сервере живьём работают файлы примерно до 700 МиБ, крупнее надо ужать (`SKILL.md`, «Размер
   файла»).
   Не включай `open_publish` для такого сервера: публиковать сможет только тот, у кого ключ.
3. Проверь настройки: `figcraft-server --config /etc/figcraft-server/server.toml check`.
4. Запусти как службу: `figcraft-server.service` из архива (пользователь `figcraft`,
   `ExecStart=/usr/local/bin/figcraft-server --config /etc/figcraft-server/server.toml`).
5. Настрой TLS через Caddy (`Caddyfile` из архива): блок с вашим доменом и
   `reverse_proxy 127.0.0.1:47900`. Caddy сам получит сертификат и пропустит WebSocket.
6. Получи адрес для публикации: `figcraft-server --config /etc/figcraft-server/server.toml key`
   печатает `…/?key=<ключ>`. Ключ работает как пароль администратора.
7. Проверь доступность: `curl https://figcraft.example.com/healthz` должен ответить `ok`.

## Как человек выкладывает файл

В приложении: **File ▸ Publish to server…**, там адрес с ключом и имя файла. Затем в **Share**
скопировать ссылку для правки и передать агенту. Можно и с кодом: в Preferences указать свой сервер
(`wss://figcraft.example.com/`) и нажать **Share ▸ Online ▸ Start sharing**.

## Ресурсы (замеры на 0.18.1)

| `.figcraft` | Пик памяти сервера | Снимок на диске |
|---|---|---|
| 219 МиБ | 1,5 ГБ | 306 МБ |
| 705 МиБ | 4,5 ГБ | 985 МБ |

- **Память.** Служба из архива ограничена 60–75 % памяти машины. Под файл около 700 МиБ бери
  машину на 8 ГБ, под файл до 300 МиБ хватит 4 ГБ.
- **Диск.** Должен оставаться свободный 1 ГиБ плюс место на два самых больших файла, иначе сервер
  перестаёт принимать изменения. Ночные копии (`figcraft-backup.timer`) занимают ещё столько же.
- **Вход.** Каждый вход передаёт весь снимок: закладывай сеть с обеих сторон.

## Облачная сессия и свой сервер

- Если прокси облака отвечает 403 на ваш домен, хост нужно разрешить в окружении: точное имя,
  без масок.
- Если сертификат выдан Let's Encrypt, хватит `FIGCRAFT_CA_FILE=/root/.ccr/ca-bundle.crt`, как
  для публичного сервера.
