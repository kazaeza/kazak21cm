# Музыкалка — архитектура

Источник требований — документ «Музыкалка — приложение для слуха и памяти» (Claude Docs).
Здесь — как эти требования превращены в код, и какие границы нельзя нарушать.

## 1. Что решаем

Диагноз: слух, ритм и руки в порядке; не хватает **имён** для звуков и **тренировки вспоминания**.
Поэтому приложение — это не набор упражнений, а машина, которая заставляет:

1. называть каждый звук ступенью (единая система координат для всех тональностей и ладов);
2. доставать материал из памяти с минимальной подсказкой, по графику интервальных повторений;
3. делать это на своей музыке, в случайной тональности, и видеть результат числом.

Главная метрика — **«Играю с ходу: N»**: вещи, сыгранные без подсказок на последнем заказе.
Если к 4-й неделе она не растёт — пересматриваем диагноз или программу.

## 2. Платформа

Нативное Android-приложение: Kotlin + Jetpack Compose, один Activity, тёмная тема.
Почему не PWA, как в исходном плане, — см. `DECISIONS.md` (ADR-001).

                  ┌─────────▼┐  ┌──▼───┐ ┌▼──────┐
                  │  audio   │  │ data │ │  ui   │      Android-модули
                  └────┬─────┘  └──┬───┘ └──┬────┘
   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ─ ┼ ─ ─ ─ ─ ┼ ─ ─ ─ ─ граница Android
                  ┌────▼─────┐  ┌──▼────────┐│
                  │ core:dsp │  │ core:game ││          чистый Kotlin/JVM
                  └────┬─────┘  └──┬─────┬──┘│          (без android.*)

| Модуль | Тип | Что внутри | Зависит от |
|---|---|---|---|
| `core:music` | JVM | Ступени, тональности, лады, аккорды в римских цифрах, гриф/строй, песни/мелодии, форматирование имён, гармония (каденции, разрешения), `Arranger` → `Score` (и тонический дрон) | — |
| `core:srs` | JVM | FSRS-6 (порт py-fsrs, дневная гранулярность), `StudyDay` | — |
| `core:dsp` | JVM | Детектор высоты (MPM), сегментатор нот, синтезатор | music |
| `core:game` | JVM | Каталог режимов/уровней, `RoundEngine` (правила!), драйверы режимов, оценка Тапёра, программа, сет дня, метрики | music, srs |
| `audio` | Android | AudioTrack-выход, AudioRecord-вход + конвейер высоты, дуплекс-гейт, TTS, выбор устройства | dsp |
| `data` | Android | Room (схема v1), DAO, DTO-пейлоады, настройки (DataStore), бэкап | music, srs, game |
| `ui` | Android+Compose | Тема, цвета ступеней, крупные компоненты (кейпад I–VII, гриф, таймер) | music |
| `app` | Android app | Навигация, 8 экранов, ViewModel'и, DI | всё |

**Жёсткие правила границ** (нарушение = отказ в ревью):

- `core:*` не импортирует `android.*`, `androidx.*`, корутины, I/O. Только stdlib (+ java.time в srs).
  Предупреждения компилятора в `core:*` — ошибки (`allWarningsAsErrors`).
- Логика игры живёт в `core:game`, а не во ViewModel. ViewModel — тонкий адаптер:
  время → `tick`, звук → `play`, микрофон → `answer`, результат → репозиторий.
- Звук наружу строится только через `Arranger`/`Score` из ступеней. Ни один экран не считает MIDI сам.
- Новые модули и зависимости — только с записью в `DECISIONS.md`.

## 4. Модель предметной области (core:music)

- **`Degree`** — ступень относительно **мажорной** гаммы тоники, всегда. В ля миноре до — это ♭3,
  в ре дорийском си — 6. Одна система координат для всех ладов: формула, выученная однажды, работает везде.
  12 канонических написаний: `1 ♭2 2 ♭3 3 4 ♯4 5 ♭6 6 ♭7 7`. ♯4 и ♭5 — разные `Degree` с одним звуком (`sameSoundAs`).
- **`DegreeNote`** — ступень + октава относительно тоники (мелодии, риффы, фразы). Текст: `5,` (ниже), `1'` (выше).
- **`Mode`** — 9 ладов (мажор, минор, дорийский, фригийский, лидийский, миксолидийский, локрийский,
  гармонический и мелодический минор), каждый — список из 7 ступеней.
- **`Key`** — тоника (с написанием) + лад. **Единственное буквенное имя, которое видит пользователь** (правило 1).
  `spell(degree)` даёт правильное написание (♭3 в ми = соль, ♯4 в до = фа-диез).
  `KeyCatalog.practical` — по одной тональности на высоту, с минимумом знаков; `KeyPicker` — случайная,
  без повторов трёх последних (правило 2).
- **`ChordDegree`** — аккорд как ступень корня + качество (`ii⁷`, `V⁷`, `♭VII`, `iiø⁷`). Парсер римской
  и арабской записи. `absoluteSymbol(key)` (Em7, F♯m7♭5) разрешён **только** на последней ступеньке подсказки.
- **`Song`** — секции (A, B…) из тактов (1–4 аккорда), форма (`AABC`), лад, стартовый лад грифа.
  Текстовый формат для сидов/импорта: `A: | iv7 | bVII7 | bIIImaj7 | bVImaj7 |`.
- **`Melody`** — одноголосная линия: `RIFF` (заказывается в Тапёре), `TUNE` («Угадай по цифрам»), `PHRASE` (фразы для Магнитофона 0.3, с `over`).
- **`Tuning`/`Fretboard`** — струна 1 = самая тонкая. Пресеты: стандарт, drop D, E♭, D, drop C♯, drop C, C.
- **`Harmony`** — диатонические аккорды любого лада, каденции для аккордовых уровней Тира (ноты — над дроном, ADR-017), **правило разрешения** в тонику
  (FET-стиль: ≤5 полутонов — вниз к 1, ≥7 — вверх к 8; хроматика сначала полутоном к ближайшей ступени лада).
- **`DegreeFormatter`/`RuNames`** — единственное место, где доменные значения превращаются в текст
  (1–7 / римские / до-ре-ми; F♯ / фа-диез; «в ми миноре»).

## 5. Как восемь правил зашиты в код

Правила — не пожелания к каждому режиму, а свойства движка. Режим физически не может их обойти.

| # | Правило | Где обеспечивается | Как проверяется |
|---|---|---|---|
| 1 | Ступени, а не буквы | Песни хранятся только в `ChordDegree`/`DegreeNote`. Абсолютные имена — только через `Key.spell`/`absoluteSymbol`/`RuNames`; разрешённые места: метка тональности, Охота ур.1–3 и обратная охота (там ноты по определению), тюнер. В Тапёре букв нет (ADR-027) | grep-ревью вызовов `absoluteSymbol(`/`spell(` в `app/` (тикет R-03 добавит тест-линтер) |
| 2 | Тональность случайная | `KeyPicker` — единственный источник тональности для Тира/Тапёра/Камертона | `MusicTheoryTest.key picker…` |
| 3 | Сначала минимальная подсказка | `HintStep` — лестница только по одной ступеньке (`next()`, до `TOP` = ступени), каждая стоит чаевых; заказ начинается со ступени затухающих подсказок (`TaperGrading.startHint`, ADR-027) | `TaperSessionTest` |
| 4 | Перебор не засчитывается | `RoundEngine`: судится только первый ответ в фазе `LISTENING`; во время подсказки микрофон закрыт; сегментатор отдаёт первую устойчивую ноту, даже если она неверна. В режиме поиска («Пропевка», ADR-028) задача ждёт верного ответа, но записывается только первая попытка | `RoundEngineTest`, `DspAcceptanceTest` (M-03) |
| 5 | Ошибся — сразу правильный ответ | `Evaluation` нельзя создать для неверного ответа на звучащий вопрос без `correction: Score`. В режиме поиска (ADR-028) correction звучит по «подскажи», на промах — подсказка словами | `RoundEngineTest` |
| 6 | Раунд 60–90 с, режимы перемешаны | `RoundConfig` отвергает другую длительность; сет дня чередует режимы (`DailySet`) | `RoundEngineTest` |
| 7 | Только твоя музыка | Тапёр и «Угадай по цифрам» берут материал только из библиотеки пользователя. Встроенный сборник (ADR-013) попадает туда только по кнопке «В мои» и дальше принадлежит пользователю | ревью, `RepositoriesTest` |
| 8 | Каждый результат — число | Движок пишет `AttemptRecord` на каждый ответ, режим не может пропустить; заказы Тапёра — `OrderLogEntity`; все метрики — запросы к этим таблицам | `RoundEngineTest` |

## 6. Игровой движок (core:game)

```
ModeDriver<T>            — мозг режима: nextTask(context) / evaluate(task, answer) / timeLimitMs
RoundEngine<T>           — чистая машина состояний раунда; время приходит параметром nowMs
   PROMPTING ──promptFinished──▶ LISTENING ──answer/timeout──▶ FEEDBACK ──tick──▶ (следующая задача | FINISHED)
RoundViewModel (app)     — играет prompt.audio → promptFinished; mic/кнопки → answer; tick каждые 50 мс;
                           на FEEDBACK играет correction; на FINISHED пишет попытки в БД и показывает итог
```

- Драйвер может держать состояние в пределах раунда (например, «корень, который ты только что сыграл»),
  но не время, звук и хранилище. Детерминирован при заданном `Random`.
- Очки: 100 + до 50 за скорость, × комбо (каждые 5 верных подряд, максимум ×4). Жизни: 3 (null — без жизней).
- Повышение уровня: последние 30 попыток уровня, точность ≥ 90 %, медиана времени ≤ цели уровня.
  Понижения нет; можно выбрать любой открытый уровень.
- Задание с дроном (`DroneTask`) может начинаться со вступления над другим дроном (`intro` над
  `introDrone`, ADR-029): новая тональность над тоникой, потом дрон задания.
- Режим поиска (`ModeDriver.searches`, ADR-028): неверный ответ оставляет задачу в `LISTENING` и растит
  `tries`; верный ведёт в `FEEDBACK`, номер попытки — в `foundOn`. Записывается только первая попытка.
- Тапёр не использует `RoundEngine`: у него свой цикл «заказ (подсказка с `startHint`) → игра → подсказки →
  самооценка → `OrderOutcome` → `TaperGrading.rating` → FSRS» (ADR-027). Экзамены — `ExamEngine`
  (фиксированное число задач, без лимита 60–90 с), использующий те же драйверы.

## 7. Звуковой конвейер

**Выход.** Один `AudioTrack` (48 кГц, float, mono, `PERFORMANCE_MODE_LOW_LATENCY`, буфер 2× burst).
Поток рендера с приоритетом `URGENT_AUDIO` тянет `Synth.render()`. Синтез без семплов:
гитара и бас — Karplus–Strong, пиано — FM e-piano, барабаны — модели на шуме/синусе, клик.
`play(score)` приостанавливает корутину до конца звучания. Без звука 10 с — трек останавливается (батарея).

**Вход.** `AudioRecord` (источник `UNPROCESSED`, если поддерживается, иначе `VOICE_RECOGNITION`;
без AGC и шумодава), 48 кГц float mono, окно 2048 / шаг 512 (~94 анализа в секунду).
`McLeodPitchDetector` → `PitchFrame` → `StableNoteSegmenter` (нота засчитывается, если держится ≥ 90 мс
в пределах ±40 центов) → `NoteEvent.Onset`. Предпочтительное устройство (USB-звуковая карта) — через
`setPreferredDevice`.

**Дуплекс** (риск «приложение слышит само себя»): пока `isSounding` и ещё 150 мс после — ноты с
микрофона отбрасываются. В режимах с бэкингом (0.3) — только с наушниками.

**Время.** Все метки — `System.nanoTime()`; задержка ответа считается от конца подсказки.
Калибровка задержки для ритмических режимов — тикет X-06 (0.3).

## 8. Данные

- Room, схема v1 (`data/schemas/` коммитится): `library_item`, `srs_card`, `order_log`, `attempt`,
  `session`, `exam_result`. Музыкальная модель хранится версионированным JSON (`payloadJson` +
  `payloadVersion`), чтобы изменения модели не требовали SQL-миграций.
- **Запрещено** `fallbackToDestructiveMigration`. Любое изменение схемы = новая версия + `Migration` +
  тест миграции + новый JSON схемы. Библиотека — это месяцы работы памяти пользователя.
- Бэкап трёх уровней: Android Auto Backup (БД + настройки в Google Drive), ручной экспорт/импорт JSON
  (SAF), и стабильный ключ подписи — обновление ставится поверх, данные не теряются.
- Учебный день начинается в 04:00 по местному времени (`StudyDay`): ночная практика — это «вчера».
- FSRS: шагов обучения нет, «фазза» нет, интервалы в целых днях; после «Again» вещь заказывается
  завтра (`maxIntervalAfterAgainDays = 1`), но S и D считаются строго по FSRS.

## 9. UI

- Экраны: Сегодня, Режимы, Игра, Библиотека (свои песни + сборник), Улов, Прогресс, Настройки, Вайб ступеней.
  Нижняя навигация — плавающая «таблетка» из четырёх вкладок: Сегодня · Режимы · Библиотека · Прогресс
  (ADR-016); Настройки — шестерёнка на «Сегодня»; Улов — кнопка «Записать свою» в Библиотеке;
  Игра, сет, Тапёр и замер — полноэкранные, без панели.
- «Сегодня» — только то, что помогает начать; вся статистика и замер уровня — в «Прогрессе».
- «Режимы» — один список всех режимов с ▶ и уровнями, без экранов-посредников (ADR-026).
- Руки заняты гитарой: в игре минимальная цель касания 72 dp, крупный шрифт, экран не гаснет.
- У каждой ступени свой постоянный цвет (`DegreeColors`) — второе, визуальное имя звука.
  Цвет никогда не единственный признак: подпись есть всегда.
- Весь текст интерфейса — по-русски. Код и комментарии — по-английски.

## 10. Сборка, подпись, поставка

- `./gradlew check` — юнит-тесты ядра, Robolectric smoke-тест запуска приложения, lint.
- `./gradlew assembleRelease` — подписанный APK (`signing/sideload.jks`, один ключ навсегда).
- `versionCode` = число коммитов; `versionName` = `versionBase.<count>` (`app/build.gradle.kts`).
- Debug-сборка имеет `applicationId` с суффиксом `.debug` и не трогает данные основной.
- CI (`.github/workflows/muzykalka.yml`): на каждый пуш — check → APK → артефакт + пре-релиз
  `muzykalka-latest` (ссылку открываешь на телефоне и ставишь).
