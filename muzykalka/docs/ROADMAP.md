# Музыкалка — роадмап и тикеты

Как читать: тикеты выполняются **сверху вниз** внутри версии, с учётом «Зависит от».
Статусы: `[x]` готово · `[ ]` не начато · `[~]` в работе. После каждого тикета —
`./gradlew check assembleRelease` зелёный, статус обновлён здесь, коммит `<ID>: <что сделано>`.

Цель каждой версии — проверить гипотезу, а не «сделать фичи»:

| Версия | Что входит | Что проверяем |
|---|---|---|
| 0, до кода | эксперимент А/Б с Autumn Leaves вручную (делает пользователь) | лучше ли держится вещь, выученная по ступеням |
| **0.1** | Охота, Тир, Тапёр с самооценкой, библиотека, Улов, повторения, вступительный экзамен | растёт ли «Играю с ходу» за 3–4 недели |
| 0.2 | Камертон с голосом, Попугай, сет дня, прогресс, зачёты | слышишь ли ноту до удара и играешь ли без перебора |
| 0.3 | Магнитофон, Диалог с бэкингом, голосовые ответы, «Радио» | превращается ли импровизация в словарь |

## Версия 0.1 — имя + вспоминание

### Звук (M)

- [x] **M-02 Детектор высоты (MPM).** `core:dsp/McLeodPitchDetector`.
  - Алгоритм: убрать DC → NSDF `n'(τ) = 2r(τ)/m(τ)`, где `r` — автокорреляция через FFT (дополнение нулями до 2N),
    `m(τ) = Σ(x_j² + x_{j+τ}²)` инкрементально → τ в диапазоне `[sr/maxHz, sr/minHz]` → ключевые максимумы
    (наибольший n' между переходом через 0 вверх и следующим вниз) → порог `k = 0.9 × max` → первый максимум
    выше порога → параболическая интерполяция → `hz = sr/τ`, `clarity = n'(τ)`.
  - `null`, если clarity < 0.5 или RMS окна < −60 dBFS.
  - Внутри `detect` — ноль аллокаций (буферы и FFT-таблицы создаются в конструкторе). FFT — свой radix-2 (`core:dsp/Fft.kt`).
  - Приёмка: снять `@Disabled("M-02")` в `DspAcceptanceTest` — все 6 тестов зелёные (синусы ±3 ц, пилы и щипки
    без октавных ошибок ±5 ц, голос с вибрато ±20 ц, шум → null, шум комнаты ±8 ц, медиана < 1 мс на окно).
- [x] **M-03 Сегментатор нот.** `StableNoteSegmenter`. Автомат IDLE → CANDIDATE → SOUNDING:
  - кадр валиден, если `clarity ≥ minClarity` и `rms ≥ gateDb`;
  - кандидат держится, пока кадры в пределах ±`maxWobbleCents` от медианы кандидата; `≥ minHoldMs` → `Onset` (медианные центы);
  - SOUNDING: невалидные кадры ≥ 60 мс → `Release`; новая устойчивая нота → `Release` + `Onset`;
  - повторный щипок той же ноты: скачок RMS ≥ 6 дБ за ≤ 30 мс → `Release` + `Onset` (повторы считаются).
  - Приёмка: 3 теста `@Disabled("M-03")` зелёные + свой тест на повторный щипок.
- [x] **M-04 Синтезатор.** `DefaultSynth`: полифония 24 голоса, очередь команд без блокировок
  (`schedule` из любого потока, `render` — только поток звука, без аллокаций), точность до семпла.
  Голоса: GUITAR — расширенный Karplus–Strong (дробная задержка через allpass, демпфирующий фильтр,
  позиция щипка); BASS — KS темнее; PIANO — двухоператорный FM e-piano с огибающей; KICK — синус 150→50 Гц;
  SNARE — шум + тон 180 Гц; HAT — высокочастотный шум 50 мс; CLICK — 1 кГц 20 мс. Мастер — мягкий лимитер.
  - Приёмка: 2 теста `@Disabled("M-04")` зелёные (замкнутая петля синтез → MPM ±5 ц; без клиппинга).
- [x] **M-05 Звуковой выход Android.** `AndroidAudioOutput` по контракту `AudioOutput`: AudioTrack float mono 48 кГц,
  `PERFORMANCE_MODE_LOW_LATENCY`, `USAGE_MEDIA`/`CONTENT_TYPE_MUSIC`, буфер = 2 × `PROPERTY_OUTPUT_FRAMES_PER_BUFFER`,
  поток рендера `THREAD_PRIORITY_URGENT_AUDIO`. `play` ждёт окончания по позиции воспроизведения; `isSounding`;
  остановка трека после 10 с тишины. Зависит от M-04.
- [x] **M-06 Звуковой вход Android.** `AndroidPitchInput`: AudioRecord float 48 кГц mono; `UNPROCESSED`, если
  `AudioManager.PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED == "true"`, иначе `VOICE_RECOGNITION`; `setPreferredDevice`;
  поток чтения → кольцевой буфер → каждые 512 семплов MPM по последним 2048 → `frames.tryEmit` → сегментатор → `notes`.
  В app: запрос `RECORD_AUDIO` (объяснение по-русски, повторный запрос, путь в настройки при «больше не спрашивать»);
  в Настройках — выбор входа (встроенный микрофон, USB-карта, проводная гарнитура; Bluetooth — с предупреждением о задержке).
  Зависит от M-02, M-03.
- [x] **M-07 Дуплекс-гейт и наушники.** Оператор над `notes`: отбрасывать ноты, пока `isSounding`, и 150 мс после.
  Определение наушников через `AudioDeviceCallback` (проводные, USB, BT A2DP) + ручной флажок в Настройках.
  Тест: синтетический поток событий → ноты во время звучания не проходят.
- [x] **M-08 «Проверка звука».** Экран из Настроек: тюнер (нота + стрелка центов, он же тюнер для гитары),
  индикатор уровня входа, кнопки проиграть каждый голос, проверка «сыграй ля — услышал?». Нужен пользователю,
  чтобы самому убедиться, что телефон слышит гитару. Зависит от M-05, M-06.
- [x] **M-09 Голос Тапёра (TTS).** `TtsAnnouncer`: `TextToSpeech` с `Locale("ru","RU")`, `say` ждёт `onDone`.
  Нет русского голоса → молча показываем текст и один раз подсказываем, как поставить голос.

### Режимы (G)

- [x] **G-01 Охота.** Драйвер `HuntDriver` + экран. Зависит от U-01, U-02, M-06, M-07.
  - Задание: высота + струна, подпись `F♯ · 5-я` (`RuNames`); для чёрных клавиш написание ♯/♭ случайно.
    Правильный ответ — любая нота этой высоты **и октавы**, существующая на этой струне в пределах `fretCount`
    (`Fretboard.notesOf`); струна — на честность.
  - Неверно/таймаут → `correction` = эта нота голосом GUITAR + подсветка позиции на грифе.
  - Уровни: 1 — струны 6,5; 2 — 4,3; 3 — все; 4 — «ступени от корня»: пара задач «сыграй корень (6-я/5-я)»
    → «♭3 на 4-й» (корень берётся из реально сыгранной ноты; драйвер хранит его в состоянии раунда).
  - Таймер сжимается: старт 5000 мс, ×0.93 за верный, минимум 1200 мс (ур.1–2) / 2000 мс (ур.3–4);
    после ошибки +20 %.
  - Выбор задания взвешенный: `1 + медиана_времени_позиции/1000 + 2 × доля_ошибок`; новая позиция — вес 2.
  - «Все октавы»: высота → сыграть во всех октавах за 15 с; каждая октава — отдельная подзадача (одна попытка = одна нота).
  - «Обратная охота»: точка на грифе → 12 кнопок имён (энгармонизмы равны), гитара не нужна.
  - itemKey: `hunt:s{string}:pc{pc}`, `hunt4:{degree}:s{string}`, `rhunt:s{string}:f{fret}`.
  - Цели повышения (медиана): 1000 / 1200 / 2500 / 2500 мс.
  - Тесты драйвера: октава засчитывается только существующая на струне; ур.4 считает от сыгранного корня; веса.
- [x] **G-02 Тир.** Драйвер `TirDriver` + экран с `DegreeKeypad`. Зависит от U-02, M-05.
  - Каждое задание: новая тональность из `KeyPicker` → каденция `Harmony.cadence(mode)` (`Arranger.chords`, 120 bpm)
    → пауза 0.4 с → вопрос. С O-02 ноты и мелодии — над дроном, тональность держится 8 вопросов (ADR-017).
  - Уровни (точно по плану): 1 — {1,3,5}; 2 — 7 ступеней лада (с ур.2 30 % заданий в миноре, кнопки = ступени лада);
    3 — хроматика (12 кнопок); 4 — мелодии из 2–5 нот (ответ — последовательность, верно только целиком);
    5 — аккорды (диатонические трезвучия, ответ — `ChordChoice`, кнопки I–VII в регистре лада);
    6 — ходы из 4 аккордов (первый всегда I/i, ответ — 3 аккорда); 7 — лады: дорийский, фригийский, гармонический минор.
  - Регистр вопроса: тоника не ниже A2 (57), с ур.2 случайная октава ±1.
  - Верно → короткое `Harmony.resolution`. Неверно → `correction` = вопрос + разрешение; на кейпаде подсвечена верная ступень.
  - itemKey: `tir:L{n}:{degree}`, `tir:L5:{roman}`, `tir:L4:len{k}`, `tir:L6:{формула}`.
  - Цели повышения: 2500 мс (ур.1–3, 5, 7), 5000 мс (4), 8000 мс (6).
  - Тесты: каждое задание содержит каденцию; ответы с энгармонизмом засчитываются; correction есть всегда.
- [x] **G-03 Тапёр.** `TaperSession` (core:game) + `TaperViewModel` + экран. Зависит от D-01, M-09, M-06 (необязательно).
  - Очередь: просроченные карточки `SrsDao.due(today)`, самые просроченные чаще; бюджет — минуты сегмента сета.
  - Заказ: `KeyPicker.next(song.mode)` → TTS «Autumn Leaves, в ми миноре!» + крупная карточка (название + тональность, больше ничего).
  - 10 секунд на старт: если микрофон доступен — первая `Onset` даёт `startLatencyMs`, иначе null.
  - Кнопка «Подсказка» поднимает `HintStep` на одну ступеньку: форма (`formString`, число тактов) → первый аккорд
    → ступени всех секций → лист целиком (`absoluteSymbol` в этой тональности — **единственное место**).
  - «Готово» → самооценка (`SelfGrade`) → «Что это было?»: ввод `TaperGrading.expectedFormula(song)` кейпадом
    аккордов (ступень + качество) → `formulaAccuracy` → `OrderOutcome` → `TaperGrading.rating` → `Fsrs.review`
    → `OrderLogEntity` + карточка → экран чаевых (числа).
  - Риффы (`MelodyKind.RIFF`) заказываются так же; «Что это было?» — ввод `DegreeNote` с октавой.
  - Тесты `TaperSession`: порядок очереди, ступеньки подсказок только по одной, рейтинг уходит в FSRS, ключ случайный.
- [ ] **G-03b «Посетитель передумал».** Для вещей со стабильностью ≥ 30 дней с вероятностью 25 % через 20–60 с
  после старта: TTS «а теперь в ре миноре!», новая тональность; в логе `keyLabel` = «E minor→D minor».
- [x] **G-04 Вступительный экзамен (0.1-часть).** `ExamEngine` (core:game): фиксированное число задач,

  Тир ур.2 × 20 (точность), Тир ур.6 × 10, Память: до 10 случайных вещей без подсказок (кнопка подсказки скрыта).

##### Памятка исполнителю O-27…O-34

Дизайн и решения ниже уже приняты — их надо реализовать, а не придумывать заново. Порядок от простого к сложному:
O-29 → O-30 → O-27 → O-28 → O-33 → O-34 (O-31 и O-32 сделаны; для O-33 готова картинка — `PitchRuler`). Один тикет —
свои коммиты. Готовые детали «Обертона» видны рядом на одном листе: `ScreenshotsTest.kit` → `10-kit.png`.

- *Язык «Обертона» (O-24…O-26), не отступать.* Чёрный тёплый фон, свет вместо плашек. Только токены `Juicy`,
  `Accents`, `Motion` (220/420/900 мс), `Numbers` (Doto — только цифры). Линии — волосяные: 1 dp, белый с
  альфой 0,07–0,16 (обычные) и 0,32 (акцент); деления как на циферблате Тира. Никаких карточек с заливкой,
  эмодзи, тряски, рывков и прыжков вёрстки: состояние меняется проявлением, свечением, ростом делений. Цвет
  ступени — только `DegreeColors`, подписи ступеней — только `DegreeFormatter`.
- *Как смотреть результат без телефона.* `MUZYKALKA_SCREENSHOTS=1 ./gradlew :app:testDebugUnitTest --tests
  '*ScreenshotsTest.tir*' -q` → `app/build/screenshots/*.png` (шейдер рисуется по-настоящему). На новый экран или
  состояние — новый метод в `ScreenshotsTest` (образец — `tirAnswered`). Смотреть картинку обязательно: «собралось»
  не значит «красиво».
- *Перед коммитом.* `./gradlew check assembleRelease` зелёный; тикет `[x]`; APK пользователю; что и как проверить
  на телефоне.

- [x] **O-27 Тир: уровни растут слишком быстро.** Отзыв: «пару раз на 100 ответил — и сразу 12 созвучий, а я ещё
  минор не выучил». ADR-037. Варианты Тира повышаются по `LevelRules.SLOW`: 60 ответов минимум из трёх разных
  дней (остальные режимы — как было). Ур. 2 учится двумя половинами: сначала только мажор, потом минор в 70 %
  блоков; ур. 3 открывается, когда освоены обе (`TirDriver.halves`, по 30 ответов на лад). Новый уровень —
  предложение: на итоге раунда кнопка «Перейти на уровень N», сам он больше не переключается. В «Режимах» у
  ур. 2 строка «мажор ✓ · минор 12 из 30». Тесты: `TirLadderTest`, `RepositoriesTest.unlockKeepsTheSelectedLevel`.
  Не покрыто тестом: нажатие «Перейти» на экране итога (проверить на телефоне).
- [x] **O-28 «Спой ступень»: трудно и быстро кончается.** Уточнено у пользователя: три жизни сгорают быстро, ошибок
  много, потому что трудно спеть ступень с ходу. Сделано: поющие режимы без жизней и по 90 с (`Drills.relaxed`);
  «Спой ступень» спрашивает только 1 · 3 · 5, пока последние 20 таких ответов не выйдут на 80 %
  (`SingDriver.steadyLearnt`), потом весь лад; промах возвращается через один вопрос — вторая попытка, пока
  свежо; после ответа линейка (O-33) показывает, насколько и в какую сторону мимо. Тоника перед вопросом была и
  раньше (без наушников — перед каждым, в наушниках — дрон). Судья не менялся (любая октава, ±50 центов).
  **Проверка на телефоне — за пользователем:** микрофон и голос в контейнере не проверить.
- [x] **O-29 Свайп между вкладками.** Свайп влево/вправо по экрану переключает Сегодня ↔ Режимы ↔ Библиотека ↔
  Прогресс.
  - *Решение.* В `nav/MuzykalkaRoot.kt` четыре вкладки сейчас — четыре назначения `NavHost`. Заменить их одним
    `TabsRoute` (стартовое) с `HorizontalPager(pageCount = 4)` из `androidx.compose.foundation.pager` (новой
    зависимости нет). `FloatingTabBar.selected = pagerState.currentPage`, `onSelect` →
    `animateScrollToPage`; `showBar` = «текущее назначение — `TabsRoute`». Колбэки `onLibrary = { tab(LibraryRoute) }`
    → прокрутка на страницу 2. `rememberPagerState` внутри `composable<TabsRoute>` — страница переживает уход в
    игру и возврат. `BackHandler(enabled = page != 0)` возвращает на «Сегодня». Остальные маршруты и их переходы
    не трогать.
  - *Конфликты жестов.* Найти `LazyRow` / `horizontalScroll` на четырёх экранах (полки сборника, гриф): внутренний
    список забирает жест первым — так и должно быть; остаток прокрутки не должен перелистывать вкладку — если
    перелистывает, дать списку `nestedScroll` с соединением, съедающим остаток по горизонтали.
  - *Тесты.* Существующие (`AppSmokeTest`: переход по вкладкам тапом) зелёные; новый: `swipeLeft` на «Сегодня» →
    виден заголовок «Режимы»; свайп по полке библиотеки вкладку не меняет.
- [x] **O-30 «Сегодня»: вместо вечного «0 песен».** Главная цифра не должна месяцами стоять на нуле.
  - *Решение (подтверждено пользователем).* Главная точечная цифра — «минут за неделю»
    (сумма длительностей сессий за 7 дней); рядом две маленькие (`Numbers.Small`): «ответов сегодня» и «дней
    подряд» (пилюля «0 дней подряд» уходит в этот ряд). «Играю с ходу N песен» показывается третьей маленькой
    цифрой, только когда N > 0. Подписи — в `strings.xml`, склонения — `plural(...)` как сейчас.
  - *Где.* `feature/today/TodayViewModel.kt` (`TodayUi` + `combine`), `TodayScreen.kt` (блок «ИГРАЮ С ХОДУ»),
    данные — репозиторий практики (`graph.practice`). Схему БД не менять: нет длительности сессии — считать по
    времени первой и последней попытки сессии; время — параметром (`nowMs`).
  - *Тесты.* Чистая функция «минуты за неделю» в `core:game` с тестом на границы недели; `TodayScreen` с нулями не
    показывает «песен пока нет» главным числом.
- [x] **O-31 Нижняя панель — иконками, не словами.** Слова «выглядели всратенько». `TabSpec(label, icon: TabIcon)`;
  знаки рисует `TabGlyph` (`ui/component/TabIcons.kt`) на Canvas — без ресурсов и зависимостей, в языке игровых
  экранов: один волосяной штрих 1,5 dp, круглые концы. **Сегодня** — циферблат Тира с шаром в центре, **Режимы** —
  четыре шара (первый залит), **Библиотека** — корешки книг, **Прогресс** — ломаная, поднимающаяся к точке.
  Выбранная — яркая, с точкой света под ней; остальные приглушены. Подпись осталась только в семантике
  (`contentDescription`, `Role.Tab`) — TalkBack и тесты находят вкладки как раньше.
- [x] **O-32 Тир: кнопка повтора крупнее.** «↻» было еле видно: глифа нет в наших шрифтах, выходил мелким и
  тонким. Теперь `ReplayKey` (`ui/component/ReplayKey.kt`): цель касания `GameTouchTarget` (72 dp), внутри
  волосяная окружность 46 dp и нарисованная стрелка по кругу; недоступна — гаснет до 0,35; нажатие — лёгкое
  сжатие. Стоит в Тире («Повторить вопрос») и в поющих режимах («Тоника ещё раз»). Строка с тональностью теперь
  72 dp во всех фазах — вопрос не прыгает. Тест: `GameFlowTest.tirReplayKeyIsBigAndPlaysTheQuestionAgain`.
- [x] **O-33 Пение: линейка с курсором.** Из health-референса: горизонтальная линейка делений с жёлтым курсором.
  `PitchRuler(offsetCents, tint, rangeCents, hitCents)` (`ui/component/PitchRuler.kt`): 30 делений в каждую
  сторону, длинные — полутона, высокое центральное — цель цвета ступени, деления в пределах ±50 центов — зона
  попадания (вырастают и светятся, когда курсор среди них); курсор `Juicy.Gold` с ▼ едет пружиной, в тишине
  гаснет на месте. На экранах пения шкала ±600 центов (любая октава засчитывается — дальше промаха не бывает).
  В «Пропевке» показывает каждую попытку, в «Спой ступень» — только после ответа (иначе это подсказка).
  Отклонение приходит из судьи (`Evaluation.centsError` → `FeedbackEvent.centsError`). Живого курсора, который

- [x] **O-34 «Обертон» в остальных игровых экранах.** «Над аккордами» и «Под нотой» идут через `TirContent` — волны и
