# Файл .figcraft: устройство и обработка

Сверено на FigCraft 0.15 и 0.18.1. Отмечено, что проверено руками, а что взято из документации.

## Что внутри (проверено)

`.figcraft` — это zip-архив:

| Внутри | Что это |
|---|---|
| `document.json` | Весь документ |
| `thumbnail.png` | Миниатюра для списков |
| `versions/<id>.json`, `versions/index.json` | История версий: полные снимки документа (в пробном файле 4 снимка по ~1 МБ, то есть примерно по размеру `document.json` каждый). Появляются не во всех файлах. `save_file` их сохраняет как есть |
| `images/<sha256>` | Картинки: ровно те байты, что были вставлены (PNG остаётся PNG, JPEG — JPEG). Имя — sha256 содержимого, поэтому одинаковые картинки хранятся один раз |

Ключи `document.json`: `format` (`"figcraft"`), `version` (1), `imageIndex`, `name`, `pages`, `nodes`,
`next_id`, `styles`, `variables`, `current_page`, `document_colors`, `comments`.

- **`imageIndex`** — список `{hash, width, height}` всех картинок в архиве.
- **`nodes`** — словарь `"<id>": {…}`. У узла `id`, `name`, `type` (`page`, `frame`, `text`,
  `rectangle`…), `parent`, `children`, `width`, `height`, `transform: [a, b, c, d, tx, ty]`
  (позиция относительно родителя — `tx`, `ty`), `fills`.
- **Заливки.** Цвета задаются от 0 до 1 (`{"r", "g", "b", "a"}`). Картинка выглядит так:
  `{"type": "image", "image": "<sha256>", …}`.
- **Текст:** `characters`, `style` (`font_family`, `font_style`, `font_size`, `line_height`,
  `letter_spacing`…), `align_h`, `auto_resize`, раскладка в `child_layout` (`sizing_h`, `sizing_v`).

Читать `document.json` полезно, когда надо понять, что занимает место. Менять его руками нельзя,
кроме вычистки картинок, как это делает `shrink_figcraft.py`. Всё остальное делай командами FigCraft.

## Из чего состоит размер

```bash
python3 -I -c "
import zipfile, sys; z = zipfile.ZipFile(sys.argv[1])
img = sum(i.file_size for i in z.infolist() if i.filename.startswith('images/'))
tot = sum(i.file_size for i in z.infolist())
print(f'всего {tot/2**20:.0f} МиБ, картинки {img/2**20:.0f} МиБ, их {sum(n.startswith(\"images/\") for n in z.namelist())}')
" файл.figcraft
```

Если почти всё картинки, файл хорошо ужимается.

## Инструменты figcraft-cli (проверено)

| Команда | Что делает |
|---|---|
| `figcraft-cli info F.figcraft` | Страницы, кадры, число узлов, стилей, переменных и картинок. Быстрая проверка, что файл открывается |
| `figcraft-cli render F.figcraft -o P.png --scale 0.05` | Вся страница в PNG: превью без открытия приложения |
| `figcraft-cli export F.figcraft -o out/ --scale 2` | PNG каждого кадра верхнего уровня, имена по кадрам (`Story.png`). `--node` — один кадр |
| `figcraft-cli convert A B` | Формат по расширению (`.fig`, `.json`, `.svg`, `.png`, `.pdf`, `.figcraft`) |
| `figcraft-cli run steps.json --out F.figcraft` | Разовый пакет команд, `{"$step": n}` ссылается на id из шага n. Живых сессий здесь нет |
| `figcraft-cli commands --filter image` | Каталог команд текущей версии (справочник в скилле `figcraft` может отставать) |
| `figcraft-cli mcp` | MCP-сервер: JSON-RPC 2.0 по stdio, одно сообщение на строку, вход до 32 МиБ на строку. Для облака: `scripts/figcraft_live.py` |

`inspect_document` принимает `allPages`, `depth`, `document`, `fields`, `maxBytes` и `outline`. Если
дерево не влезло, в ответе будет `truncated`: подними `maxBytes` или сузь `fields`.

## Картинки (проверено)

- `image.place {path | data, x, y, width?, height?, parent?, mode?}` вставляет картинку слоем.
  Картинка — не больше 65 535 px по стороне и 256 МиБ в раскодированном виде.
- `image.replace {ids, index?, path | data}` подменяет картинку в заливке, сохраняя режим, кадрирование
  и положение. **Старая картинка остаётся в файле** даже после повторного открытия, сохранения и
  `convert`. Убрать её помогает только вычистка архива (`shrink_figcraft.py`, функция `prune`).
- Команды «удалить неиспользуемые картинки» в 0.18.1 нет, `inspect.assets` их не показывает.
- Отдельной команды сжатия тоже нет. Сжатие делается так: уменьшить картинку снаружи (Pillow),
  подменить через `image.replace`, вычистить старые. Скрипт `shrink_figcraft.py` делает это сам:
  картинки без прозрачности уходят в JPEG, с прозрачностью — в PNG. Альфа-канал, где всё
  непрозрачно, прозрачностью не считается.

## Тексты (проверено)

- `edit.findReplace {find, replace}` не различает регистр и возвращает `{"matches": [ids]}`.
- Он меняет текст, но не имя слоя. Слой, созданный с текстом, называется по тексту и сохранит
  старое имя.
- Кириллица во встроенных шрифтах (Inter и др.) есть. Цветных эмодзи во встроенных шрифтах нет:
  нативный CLI сам берёт системный цветной шрифт (в облаке Noto Color Emoji), а веб-версии нужно
  разрешение, см. `web-build.md`.
- **Цветной эмодзи обрезается, если рисуется крупнее ~110 px.** Считается размер шрифта ×
  масштаб экспорта или зума. Проверено и в CLI 0.18.1, и в веб-версии 0.15: 160 px × 0,5 цел,
  260 px × 0,5 = 130 px обрезан, 96 px × 1 цел. Для печати с `--scale 2` держи текст с эмодзи до
  ~50 px. Монохромный ❤ так не обрезается.
- **Совместимость.** `figcraft-cli` 0.18.1 открывает и экспортирует файл, сохранённый веб-версией
  0.15.
