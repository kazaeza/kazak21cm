# FigCraft в облаке: что, как и куда

Сводка на 2026-11-20. Подробности и проверенные команды лежат в скилле `.claude/skills/figcraft-server/`.

## Коротко

- Облачная сессия **не видит ваш ПК**. Файлы надо один раз передать через хранилище (Яндекс Диск или Dropbox), я скачиваю их, правлю и кладу результат обратно.
- **Ужимать и дробить всё подряд не надо.** Ужимаем только файлы тяжелее ~700 МиБ (в первую очередь «Меню гусси»), и только **копию**.
- **Дробить файл не советую.** Файл FigCraft — один архив: страницы, компоненты и стили связаны между собой, безопасного способа разрезать его нет.
- Сначала проба на маленьком файле, потом гигабайт.

## Что умеет облако (проверено)

| Что | Значение |
|---|---|
| Ресурсы | 16 ГБ памяти, 4 ядра, ~30 ГБ диска |
| Сеть | исходящая без ограничений, входящих соединений нет |
| Скачивание 1 ГиБ через прокси | целиком, за 54 с (~20 МБ/с) |
| Достижимы | `cloud-api.yandex.net`, `disk.yandex.ru`, `www.dropbox.com`, `drive.google.com`, `storage.googleapis.com`, `s3.amazonaws.com` |
| Открыть, поправить и сохранить файл на 961 МиБ | 7,5 с, пик памяти 3,5 ГБ |
| До вашего ПК | не дотягивается. Папки Remote Control (`figCraft`, `Комиксы`, `VK Tasker`) облаку не отдаются (`not_available`), скорее всего, нужно обновить Claude на ПК |

## Шаг 0. Узнать размеры файлов

В PowerShell на ПК:

```powershell
Get-ChildItem -Recurse -Filter *.figcraft | Sort-Object Length -Descending | Select-Object @{n='МБ';e={[math]::Round($_.Length/1MB)}}, FullName | Format-Table -AutoSize
```

Пришлите мне вывод: имена и размеры, содержимое не нужно.

## Что делать с файлом по размеру

| Размер `.figcraft` | Что делаем |
|---|---|
| до 8 МиБ | Можно через публичный сервер: **Share ▸ Online ▸ Start sharing**, присылаете мне код. Минусы: файл на сервере не шифруется, удаляется через 30 дней без заходов. Для закрытых проектов лучше хранилище |
| 8–700 МиБ | Ничего не ужимаем, работаем как есть |
| больше 700 МиБ | Ужимаем копию: картинки до 2048 px по длинной стороне (для печати ~3600 px). Макет остаётся цельным, показываю кадры «до и после» |

Ужатие на тестовых файлах: 961 → 219 МиБ (шумовые RGBA-картинки), 187 → 1,6 МиБ (фотоподобные). Исходник не трогается.

## Куда что класть

Выберите **одно** хранилище, Яндекс Диск или Dropbox, и заведите в нём папку `figcraft-work`:

```
figcraft-work/
  in/     <- ваши КОПИИ файлов (исходники оставляйте у себя)
  out/    <- мои результаты: новые файлы с другими именами
```

- **В облако.** Вы кладёте копию в `in/` и даёте мне ссылку на файл или папку. Я скачиваю её и работаю.
- **Обратно.** Я кладу готовое в `out/` под новым именем (например, `menu-edited.figcraft`). Для записи мне нужен ваш ключ доступа. Он вводится **только через защищённую форму** (я её вызову, когда дойдём до этого), в чат ключ не пишите. Исходники я не перезаписываю.
- Ссылки, коды, токены и ключи я не пишу в файлы репозитория и логи.

## План по шагам

1. Вы присылаете вывод из шага 0.
2. **Проба:** вы кладёте в `in/` один маленький проект (до 20 МБ), даёте ссылку. Я скачиваю, правлю текст, кладу результат в `out/`. Так проверяется весь путь в обе стороны.
3. **«Меню гусси»:** вы кладёте копию в `in/` (залив гигабайта из браузера занимает время, это нормально). Я скачиваю её за ~1 минуту, смотрю, из чего состоит размер, ужимаю копию и показываю кадры до и после.
4. Дальше работаем одним из двух способов.

## Два способа работы

| Способ | Как | Когда |
|---|---|---|
| **Файл туда-обратно** (по умолчанию) | Я правлю файл напрямую (`open_file` → правки → `save_file`), результат кладу в `out/` | Почти всегда: просто и проверено |
| **Вживую, как в Figma** | Свой `figcraft-server` на VPS, вы публикуете файл из приложения (**File ▸ Publish to server…**), я захожу по ссылке | Когда нужна совместная правка в реальном времени. Нужен VPS: 4 ГБ памяти под файл до 300 МиБ, 8 ГБ под файл до 700 МиБ |

## Лимиты, которые нужно помнить

| Ограничение | Значение |
|---|---|
| Публичный сервер `collab.craftapps.dev` | файл до 8 МиБ, удаляется через 30 дней простоя, без шифрования |
| Свой сервер | `max_file_mb = 1023` максимум: клиент не заходит в файл, снимок которого больше 1024 МБ |
| Снимок на сервере | примерно в 1,33 раза больше `.figcraft` (картинки хранятся в base64) |
| Живая работа | практически до ~700 МиБ; 961 МиБ через сервер не проходит ни при каких настройках |
| GitHub | до 100 МБ на файл: тяжёлые `.figcraft` туда не кладём |
| Обрезка эмодзи | цветные эмодзи обрезаются, если рисуются крупнее ~110 px (размер шрифта × масштаб экспорта) |
| `image.replace` | старые картинки остаются в архиве, потом нужна чистка (её делает скрипт ужатия) |

## Что проверено, а что нет

**Проверено на настоящих `figcraft-cli` и `figcraft-server` 0.18.1:**
- заход в файл по коду и ссылке, правки вживую, ссылка «только просмотр»;
- публикация на свой сервер (локально), работа с файлами 219 и 705 МиБ;
- ужатие картинок: рендер до и после совпадает, прозрачность сохраняется;
- скачивание 1 ГиБ через прокси, доступность хранилищ;
- открытие, правка и сохранение файла на 961 МиБ.

**Не проверено:**
- обмен с **вашим** хранилищем (нужна ссылка или ключ, поэтому и нужна проба);
- свой сервер на VPS через настоящий интернет (TLS, Caddy);
- вход по ссылке, выданной десктопным приложением (а не `figcraft-cli`).

## Запасные пути

- **Локальная сессия на ПК** (Claude Code на вашем компьютере): файл никуда не едет, работаем прямо с папкой.
- **Remote Control:** папка `figCraft` уже есть в списке. Если обновить приложение на ПК и она станет доступна облачной сессии, заливать ничего не придётся.
