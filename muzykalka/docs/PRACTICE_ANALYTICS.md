# S-01 · Аналитика практики и адаптивный слуховой блок

«Прогресс → Экспорт статистики» сохраняет JSON формата `muzykalka-practice`, версия 2. Снимок читается одной транзакцией. Обычный бэкап в настройках нужен для восстановления библиотеки.

- `attempts` — исходные ответы. У строки есть id, sessionId (может отсутствовать), режим, уровень, ключ задания, ожидаемый и данный ответ, правильность, задержка в мс, тональность, время Unix в мс и центы там, где они измеряются. В «Пропевке» сохраняется первая попытка. В старых данных пауза могла сдвинуть время события назад. Нулевое hintLevel в упражнениях не подтверждает отсутствие повторного прослушивания.
- `sessions` — начало, конец, тип и учебный день. С версии 2 для сета пишутся программа, вариант слухового задания, пара, уровень, конкретный аккорд при наличии, причина и ссылка `focusParentId` на исходную дуэль. `focusStatus`: ASSIGNED — исход неизвестен, SKIPPED — явный пропуск, INTERRUPTED — прерванный раунд, EMPTY — раунд завершился без ответов, COMPLETED — завершился с ответами. Старые строки сохраняются с пустыми новыми полями.
- `attempts.focusRound = true` отмечает ответы именно из назначенного слухового раунда. `replayCount` в новых раундах считает повторы до первого ответа, включая повтор при возвращении с паузы. `songSectionKey` в сете — запланированная часть песни. Реальную попытку можно найти по sessionId и ключу задания (`formula:…` для воспоминания, `song-steps:…` для перехода на гитаре).
- `orders` — отдельное исполнение песни или риффа, подсказка, самооценка, тональность и результат FSRS. formulaAccuracy = -1 означает, что вопрос не задавался. `exams` — результаты по навыкам, связанные с сессиями.
- `appVersion`, `exportZone` и `dayStartHourAtExport` — значения на момент выгрузки. Исторические настройки устройства неизвестны. Выгрузки полные и перекрываются. Для одного непрерывного экземпляра базы анализировать последний снимок. Времена ответов разных задач и самооценок несопоставимы.

## Пилот S-01

«Сет дня» и «Слух» отдают один 90-секундный блок из имеющегося времени. Окно поиска путаницы — 14 учебных дней. Нужны ошибки на одной паре в разные дни на одном уровне и хотя бы четыре предъявления каждой ступени. Введённый вручную свободный раунд и пропущенное назначение не начинают цепочку проверок.

После завершённой дуэли с ответами на обе ступени на следующих учебных днях возвращается полный круг. В него подмешиваются обе цели и обычные вопросы. Для каждой ступени берётся только первое предъявление в день в завершённой связанной проверке. Повторное прослушивание исключает это наблюдение целиком. При трёх наблюдениях на каждую ступень и точности от 80% на каждой предлагается исполнить проверку над аккордами, если эти ступени есть в используемых ладах. Один промах продлевает наблюдение. Две ошибки на одной ступени в разные дни при точности ниже порога возвращают к сравнению пары. На 14–20-й день после дуэли есть повторная проверка сохранения результата, если первичная проверка пройдена. Здесь для каждой ступени нужны два дня наблюдений. Две ошибки на одной ступени возвращают дуэль. Это рабочие пороги пилота. Смена настроек границы дня может изменить окно обычных попыток. Сессии используют сохранённый учебный день.

Второе основание для гармонического задания — разрыв от 20 п.п. на сопоставимых ступенях одного лада на фоне аккорда и над тоникой. Для конкретного аккорда нужны три общие группы, от трёх ответов и двух дней на каждую группу в каждом условии. Фактически сыгранный аккорд записан в ключе задания. Общий процент по двум режимам сам по себе ничего не назначает.

В программах «Песни в голове» и «В дороге» первое предъявление возвращает часть песни из активной библиотеки, которую в предыдущие 13 учебных дней оценили «с запинками» или «не вспомнил». Чистое последующее воспоминание закрывает эту задачу. Дорожный вариант заменяет двухминутный блок, формулу можно вспомнить молча. «Гитара в руках» проверяет первый переход между разными аккордами этой же части. Успех по памяти и исполнение записываются раздельно. Оба результата — самооценка. Карточку FSRS по-прежнему обновляет исполнение заказа.

Для анализа считать первые проверочные ответы и объём выборки по каждой ступени. Раздельно смотреть начальный перенос и сохранение через две недели, показывать долю пропусков и число повторных прослушиваний. Эти наблюдения не устанавливают причинный эффект программы.

Интервалы и пороги подлежат проверке на практике. Основания для разнесённых проверок и для смены гармонического контекста: [Cepeda et al., 2008](https://pubmed.ncbi.nlm.nih.gov/19076480/) и [Arthur, 2018](https://doi.org/10.1525/mp.2018.35.3.295).
